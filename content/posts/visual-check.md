## 从素材开始，保留每一次尝试

一支短片的起点，往往不是打开剪辑软件，而是把手边的素材整理清楚。哪些镜头交代环境，哪些画面带出情绪，哪一句话值得保留？先回答这些问题，后面的选择才会变得具体。

这段文字用来观察中文与 English、数字 4K / 25 fps 的混合排版。**好的工作流应该让人更专注于内容。** 工具负责重复劳动，创作者负责判断：这个镜头是否必要，这一处停顿是否自然，这句话是否说到了点上。

> 先留下真实的瞬间，再决定怎样讲述它。剪辑的作用，是让那些值得被看见的细节，获得合适的位置。

### 整理素材的三个步骤

1. **保留原始文件。** 为每次拍摄建立独立文件夹，让素材与导出版本各自归位。
2. **选出关键镜头。** 把开场、细节和结尾分别记录下来，标注清晰的时间点。
3. **写下这一版的目标。** 一次只解决明确的问题，避免每轮修改都重新开始。

## 每次交付之前，认真检查

一段视频可以顺利导出，不代表已经完成。我们还需要完整地看一遍：字幕有没有遮住脸，声音是否清楚，镜头切换是否合理。

- **画面：** 保留原始比例，检查裁切与安全区域。
- **声音：** 对白清楚，音乐和音效不抢主体。
- **字幕：** 校对人名、术语与标点，避免自动转写的误差。
- **版本：** 保留可回退的记录，写明这一版具体改了什么。

> [!NOTE]
> 把“已生成”“已检查”和“已确认”分别记录。只有看过完整成片，才能判断修改是否真的解决了问题。

## 把重复的步骤变成工作流

下面是一段示例配置。代码块使用等宽字体，与正文保持清晰的区别；较长的内容可以换行，不会把手机页面撑出屏幕。

```json
{
  "project": "rubyfpv-short-film",
  "source": "originals/",
  "output": "exports/review-v01.mp4",
  "format": { "width": 1080, "height": 1920 },
  "review": ["picture", "audio", "captions", "continuity"]
}
```

发布一篇新文章时，在 `content/posts/` 中添加 Markdown 文件，填写标题、日期、分类和封面信息。文章目录会根据二级、三级标题自动生成。

```bash
npm run dev
# 本地预览包含草稿

npm run build
# 正式构建排除 draft: true 的测试文章
```

## 留下下一次创作的起点

每一次整理、剪辑和复看，都会留下新的经验。把有效的方法写下来，把没有解决的问题保留下来，下一次创作就能从更清晰的位置开始。
